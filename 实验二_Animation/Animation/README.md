## 示教编程与连续执行

打开“示教编程”。用左侧示教器调整并停稳，点“记录当前位姿”，至少记录4个不同位姿；点“按记录顺序生成程序”得到 `MOVJ P1` 等指令，可在文本框调整行的顺序。使能后点击“执行程序”，各关节按共同进度同步插值到位，再执行下一条 MOVJ。停止、急停、失能或切换任务都会中断程序，需手动重新执行。

“载入 360° TCP 环绕扫描”生成 P1～P25 共 25 个位姿：TCP 在世界 XZ 水平面绕目标中心、半径 0.6 资产单位运动，J1～J4 由位置逆运动学求解，J5 从 −180° 同步转到 +180°。黄色圆线和红色圆点显示目标路径及圆心。先到 P1，再顺序执行到 P25；MOVJ 关节插值使实际路径近似圆，段间会停顿。运行时自动记录 TCP 轨迹，完成后可在“轨迹分析”导出 CSV。模型没有相机成像，逆解没有姿态朝向约束。更改 TCP 标定后须重新载入预设；碰撞保护仍会中断程序。

程序只支持每行 `MOVJ P编号`。运行前检查至少4个不同位姿及关节限位。位姿记录包含关节角，手动采集时同时保存当前 TCP 世界矩阵。记录、撤销、清空、生成、载入和导入时会尝试保存到当前浏览器本地；手动编辑指令文本后请导出 JSON 保存，避免未保存的更改丢失。计算测试：`node js/tests/program.test.mjs`。

## 四点法 TCP 标定（张云乔 · 实验二第 2 章）

在“TCP 标定”中，让同一工具尖端以至少 4 种充分分散的姿态接触同一个固定点，停稳后点击“采集当前法兰位姿”。保持固定点不动，保存法兰世界矩阵和关节角；采样不依赖当前设定的 TCP。重复位姿会被拒绝。可撤销、清空，最多保留 100 组。法兰原点共面、近共面或重合时不能使用球心法，应重新分散采样。

点击“拟合球心与 TCP 偏移”查看球面 RMS、接触一致性 RMS 和最大接触误差。仅在最大误差不超过设定容差时允许应用。默认容差为 0.01 模型单位，需按实验测量精度设置。四点法只辨识平移，工具 RPY 需由已知安装方向给定；界面角度为度，函数 RPY 数组为弧度。也可保留实验一流程，手工应用已知工具偏移。更换工具会使原用户坐标系失效；持有工件时禁止更换工具。

“算法演示数据”可载入 4 个理想接触位姿，已知法兰系偏移为 `[0.2, 0.4, 0.8]`，世界接触点为 `[2, 3, 4]`。该功能不移动机械臂，所有记录均标记为 `synthetic-demo`，不能作为实测精度证明，也不能与实际接触采样混用。

### 算法及接口约定

令第 i 组世界←法兰变换为 `T_i=[R_i,p_i]`，固定接触点为 `c`，法兰系 TCP 偏移为 `t`，则 `R_i t + p_i = c`，法兰原点满足 `||p_i-c||²=r²`。对法兰原点中心化、归一化后，以带列主元 QR 求解球心最小二乘问题，再平均 `T_i^-1 c` 得到局部偏移。支持各位姿一致的正均匀缩放，拒绝非均匀缩放、反射、剪切和奇异矩阵。

四个非共面点总能定义一个球，因此球面径向残差接近零并不代表工具标定正确。实现另行计算每组重建尖端 `T_i t` 到固定点 `c` 的误差；接触残差与球面残差分开显示、保存和检查。QR 的 `condition` 是对角元素比值指标，不是精确条件数。

```js
import { fitSphereCenter, fitTCPFromPoses } from './js/Calibration.js';

const sphere = fitSphereCenter(points); // Vector3[] 或 [x,y,z][]，至少4点
// sphere: {center: Vector3, radius, residuals, rms, maxResidual, condition, sampleCount}
const tcp = fitTCPFromPoses(poses); // Matrix4[] 或 number[16][]，列主序，世界←法兰
// tcp: {offset: Vector3, center: Vector3, sphere, localOffsets, residuals,
//       rms, maxResidual, sampleCount, scale}，residuals 为世界空间接触误差
```

核心修改为 `js/Calibration.js`、`js/calibration-panel.js`、`js/Workstation.js`；`index.html` 提供操作入口，`js/robot-model.js` 完成最小接线。原有本地 three.js 0.186.1、目录约定及 Live Server 工作流保持兼容。

### 夹爪与组员 C / D 接口

在“工位场景”中先将 TCP 对准物块顶面中心并停止运动，再执行 CLOSE。距离不超过 `blockSize * 0.2` 时挂载到法兰，远处闭合为空夹。OPEN 把工件挂回场景，保留释放时的世界位置、旋转和尺度，不会自动返回原点。单独的“复位工件到工作台”用于重置实验。几何夹爪可视化随当前 TCP 偏移变化；没有重力仿真，释放的物体停留原处。抓取、释放或复位后用户坐标系失效。

桌面放置点仍按工作台的局部坐标计算，工件初始/复位后直接属于场景，与工作台几何分开，避免旧碰撞检测把目标工件扩进桌子包围盒而阻止接近。工位页实时显示 TCP 到顶面抓取点的距离。

```js
// 组员 C：在上一段运动结束后调用；急停/运动未停会抛错。
const result = window.robotSimulation.grip('CLOSE'); // 或 'OPEN'
// {state, attached, distance, tolerance, canGrab}
// CLOSE 后检查 attached；false 表示空夹，执行器可据此报错或暂停。

// 底层场景图函数：只保留世界变换并切换父节点，不做安全/距离检查。
import { attachWorkpiece, detachWorkpiece } from './js/Workstation.js';
attachWorkpiece(flange, wp);
detachWorkpiece(scene, wp);

// 组员 D：夹爪为 Group，可遍历其中掌部/左右指 Mesh 做碰撞检查。
const { gripper, workpiece, table } = window.robotSimulation.workstation;
```

夹爪碰撞检测、MOVL 和 DSL 解析器仍由对应组员实现，本模块提供调用与几何对象接口。全链路搬运演示需等这些模块合入后联调。

## 用户坐标系三点法

先应用 TCP，再点动到 O、X、XY 三个标记点并采集，或输入独立测量的世界坐标：O 为原点，O→X 为 +X，第三点确定 XY 平面及 +Y 一侧。程序以施密特正交化建立正交右手坐标系，拒绝重合和共线点。改变 TCP 后原用户系失效，必须重新采集/建立。

检查三点在用户系中的轴向约束、旋转矩阵行列式和正交误差。再输入一个独立世界点验证“世界→用户→世界”的往返误差。往返误差检查变换计算一致性，不能单独证明实测标定精度；现场精度还需对比已知标记点的测量值。

## 轨迹分析与可达区域（王静）

“轨迹分析”和“可达区域”两个页签对应实验要求 c、d：

- **轨迹分析**：扫描程序执行时自动记录；其他程序可先点“开始记录”。模块逐帧读取 `tcp` 节点世界坐标，绘制轨迹 XZ 俯视图、位置曲线 p(t)、速度曲线 v(t)，可导出 CSV。速度由相邻采样差分得到。
- **可达区域**：按真实关节限位随机采样 2 万组关节角，经场景树正运动学生成 `THREE.Points` 点云，统计水平半径、高度范围、空腔占比与最大空洞，并显示工件原点到最近采样点的距离与页面判断。

实现：`js/analysis/TrajectoryCharts.js`、`js/analysis/WorkspaceCloud.js`，`js/analysis/analysis-panel.js` 负责接线，页面入口在 `index.html` 末尾。
数据口径：长度单位沿用**资产单位**（未换算为米）；点云随机种子固定 `20261026`，结果可复现。分析与结论见 [第五章](第五章_轨迹与可达区域分析.md)。
